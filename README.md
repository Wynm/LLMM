## لماذا مِشكاة؟

معظم أدوات «الذكاء الاصطناعي» العربية واجهةٌ رقيقةٌ فوق خدمةٍ سحابية مغلقة: لا
تعمل بلا شبكة، ولا تُفصح عن خطواتها، ولا تفهم بنية اللغة العربية (جذر، وزن،
صرف). ومِشكاة يقوم على العكس: **كل شيء محلّي، وكل نتيجة تُرفَق بسببها.**

| المبدأ | الترجمة العملية |
| --- | --- |
| الاستقلال | لا شبكة، لا مفاتيح، لا تبعية سحابية |
| الشفافية | كل نتيجةٍ معها مصطلحاتها وجذورها ورتبها وزمنها |
| العمق اللغوي | تطبيع، تقطيع، إيقاف، تجذيع، أوزان صرفية، إعلال |
| البناء من الصفر | الفهرس، BM25، HNSW، PPMI+SVD، الرسم، المحوّل — كلها هنا |
| القابلية للقياس | اختبارات، اختبارٌ ذهبيّ، تقرير أداء، سجلّ تطوير |

## ما يفعله

| الطبقة | الوصف |
| --- | --- |
| **النواة اللغوية** | أربعة مستويات تطبيع (عرض/خفيف/بحث/صارم)، تقطيعٌ بمواضع، ٢٤٠+ كلمة إيقاف، مُجذِّع Light-10، واستخراج جذرٍ بالأنماط مع معالجة حروف العلّة (دقّة **97%** على مجموعةٍ ذهبية). |
| **الاسترجاع** | فهرسٌ مقلوب بحقولٍ موزونة ومواضع، BM25، لغة استعلام (عبارة/إلزام/استبعاد/سابقة)، **HNSW** مكتوبٌ يدويًّا (استدعاء@10 = 1.0)، ودمجٌ هجين «معجميٌّ أولًا»: المعجم يقرّر، والدلالي يُعزّز ويُلحق (RRF متاحٌ للمقارنة — قياسٌ في الأسفل). |
| **الفضاء الدلالي** | تجاور ← PPMI ← **SVD مضغوط عشوائيًّا** ← متجهات كلماتٍ ومستندات + تجميع k-means. |
| **الرسم المعرفي** | ١٧٥ عقدة (مستند/شخص/مكان/مفهوم/نطاق)، ٢٥٤ حافة، لغة **MQL** بمحلّلٍ يدويّ، واستدلالٌ بالقواعد مع إثبات كل حافةٍ مستنتجة. |
| **المحوّل العصبي** | Transformer حرفيّ بـ **NumPy فقط**، انتشارٌ خلفيّ يدويّ مُتحقَّقٌ عدديًّا، Adam + جدولة جيبية، وتوليدٌ بـ temperature/top-k. |
| **الاستوديو** | واجهة RTL بلا خطوة بناء: بحث، إبراز، رسم قوى على Canvas، خريطة مواضيع، مختبر نصّ، لوحة إحصاءات. |

### حدود المحوّل — بصراحة

المحوّل **نموذجٌ توضيحيّ** لا محاور: ٢٣٧,٥٠٤ وسيطًا تدرّبت على ٤٩,٨٨٤ حرفًا
فقط (2600 خطوة، 7.7 دقيقة على نواتين، خسارة 5.33 ← **1.246**، أفضل حجز
**1.926**). الناتج عربيُّ الشكل، صحيحُ المورفولوجيا تقريبًا، بلا تماسكٍ دلاليّ:

> «العلمة إلى صارت والصنعة؟ القيمة سبعد عمل بقرون، ودورةُ حسابٌ واحد…»

قيمته أنه **مفهومٌ بالكامل**: كل تدرّجٍ مكتوبٌ يدويًّا ومُتحقَّقٌ عدديًّا في
الاختبار. مسار التحسين واضح: مجموعةٌ أكبر (200 مستند) ونموذجٌ أوسع.

## البدء السريع

```bash
git clone <repo> && cd LLMM
make bootstrap          # تثبيت المتطلّبات (numpy, fastapi, pytest …)
make test               # 264 اختبارًا
make build              # بناء كل الفهارس (≈ 9 ثوانٍ)
make run                # الاستوديو على http://localhost:8000
```

بلا شبكة، وبلا أي مفتاح API. الواجهة والـ API من نفس الخادم.

### سطر الأوامر

```bash
python -m mishkat.cli search "كيف قاس البيروني الأرض؟"
python -m mishkat.cli stats
python -m mishkat.cli roots المدارس استخدام برمجة
python -m mishkat.cli analyze "العلم نور والجهل ظلام"
python -m mishkat.cli graph 'MATCH (?x) -[ألّف]-> (?y) LIMIT 5'
python -m mishkat.cli train --steps 2200 --lr 2e-3
python -m mishkat.cli generate "العلم" --length 200
python -m mishkat.cli bench
python -m mishkat.cli eval --misses 5
```

### واجهة HTTP

| المسار | الوظيفة |
| --- | --- |
| `GET /api/search?q=…&mode=hybrid` | بحث + أثر كامل (مصطلحات، جذور، رتب، أزمنة) |
| `GET /api/doc/{id}` | مستند + تحليل + علاقات + جيران |
| `POST /api/graph/query` | تنفيذ MQL |
| `GET /api/words/{w}/neighbors` | جيران الكلمة في الفضاء الدلالي |
| `GET /api/space/map` | إسقاط المستندات إلى 2D |
| `POST /api/analyze` | تحليل نصّ كلمةً كلمة |
| `GET /api/lm/generate` | توليد من المحوّل المدرَّب |
| `GET /api/stats` | كل المقاييس |

## الاختبارات والقياس

```bash
make test     # 264 اختبارًا: نصّ، فهرس، HNSW، رسم، فضاء، محوّل، API، تقييم
make bench    # تقرير أداء (زمن كل مرحلة، استدعاء HNSW مقابل الشامل)
make eval     # جودة الاسترجاع على 59 استعلامًا مُعنونًا
```

- **الجذور**: 64/66 على مجموعةٍ ذهبية مُعنونة (`data/eval/roots.jsonl`).
- **HNSW**: استدعاء@10 = 1.0 على 1000 متجه مقابل البحث الشامل.
- **التدرّجات**: كل تدرّجٍ في المحوّل مُقارَنٌ بتقديرٍ عدديّ في الاختبار.

### جودة الاسترجاع — أرقام لا انطباعات

على `data/eval/queries.jsonl` (59 استعلامًا، تصنيفٌ آليّ للاستعلامات بحسب
تطابق الجذوع) مقابل مجموعةٍ من **82 مستندًا**:

| الاستراتيجية | MRR@10 | Recall@10 | Hit@1 | زمن/استعلام |
| --- | --- | --- | --- | --- |
| معجميّ (BM25) | 0.992 | 0.994 | 0.983 | 2.1 ms |
| دلاليّ (متجهات) | 0.924 | 0.983 | 0.881 | 3.0 ms |
| RRF (الشائع) | 0.960 | 0.994 | 0.932 | 5.8 ms |
| دمجٌ متساوٍ بالدرجات (w=0.85) | 0.966 | 1.000 | 0.932 | 4.4 ms |
| **هجين «معجميٌّ أولًا» — المُشحون** | **0.992** | **0.994** | **0.983** | **10 ms** |

**قراءة صادقة:** على مجموعةٍ صغيرةٍ متباينة المواضيع يتفوّق المعجميّ وحده في
الدقّة. والهجين لا يتجاوزه، بل **يُساويه في الدقّة ويضيف تغطية** من المسار
الدلالي. وقد جرّبنا ثلاث تصاميم للدمج: RRF (0.960)، الدمج المتساوي بالدرجات
(0.966)، ثم «معجميٌّ أولًا» (0.992). درسٌ موثَّق في
`docs/03-devlog.md`: وزنٌ مُعايَرٌ على 59 مستندًا انهار حين صارت 82؛ فاخترنا
تصميمًا يعتمد على **من يقرّر الترتيب** لا على رقمٍ مضبوط.
